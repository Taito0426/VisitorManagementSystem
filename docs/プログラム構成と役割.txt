════════════════════════════════════════════════════════════════════
  ★ 本システムの中核：DB切替アーキテクチャ（設計書 4章）
════════════════════════════════════════════════════════════════════
  appsettings.json の Database:Provider を書き換えて再起動するだけで、
  SQL Server Express（オンプレ版）と Azure SQL Database（クラウド版）を
  切り替えられる。ビルドの出し分けは行わず、同一バイナリで両対応する。

    { "Database": { "Provider": "SqlExpress" } }   // "SqlExpress" | "AzureSql"

  切り替わるのは次の4種類の実装のみで、Repository層のSQL文・業務ロジック・
  画面はすべて共通コードである（差分の局所化）。

    IDbConnectionFactory   SqlExpressConnectionFactory  / AzureSqlConnectionFactory
    IDbRetryPolicy         NoRetryPolicy                / AzureSqlRetryPolicy
    IBackupService         SqlExpressBackupService      / AzureSqlBackupService
    IArchiveStorage        LocalArchiveStorage          / AzureBlobArchiveStorage

  ★切替の登録は VisitorManagement.Composition\ServiceCollectionExtensions.cs
    の AddDatabaseProvider ここ1か所。

  2. VisitorManagement.Application  ── アプリケーション層
                                       業務ロジック・ユースケース
════════════════════════════════════════════════════════════════════

  ■ Exceptions
  ----------------------------------------------------------------
  BusinessRuleException.cs    業務ルール違反（入力不備・状態不整合）。
                              メッセージはそのままユーザーへ提示できる。
  PermissionDeniedException.cs 権限不足。ForOperation("操作名") で生成。

  ■ Services（各業務サービス）
  ----------------------------------------------------------------
  AuthenticationService.cs  ログイン認証。ID不存在時もダミーハッシュを検証して
                            応答時間をそろえ、アカウント列挙を防ぐ。失敗理由
                            （ID誤り/PW誤り/無効化）は呼び出し側に区別させない。

  ReservationService.cs     ★来館予約の中核（設計書 6.1/6.2/6.6/6.7節）。
                            ・CreateAsync＝代表者＋同行者を1トランザクションで登録し、
                              QRトークンを代表者行にのみ1件発行してメール送信。
                              当日受付は予約登録者宛の控えを省略する。
                              ★当日受付は「登録＝入館」として扱う（設計書からの変更）。
                                発行時刻でグループ全員を「入館中」にし、全員分の入館履歴を
                                同一トランザクションで記録する。QRトークンは UsedCount=1
                                （読取済み）で発行するため、発行したQRの最初の読取が
                                「2回目＝退館」として処理される。
                            ・UpdateAsync＝同行者の増減にも対応。予約日時が変わると
                              未使用トークンの有効期限を追随させる。
                            ・CancelAsync＝グループ全員をキャンセルしトークンを無効化、
                              招待者へキャンセル通知。
                            ・DeleteAsync＝入退館記録がある予約は削除不可（キャンセルを使う）。
                            ・ResendMailAsync＝有効期限内かつ未使用なら既存トークンを再送、
                              期限切れなら期限を再計算して延長（いずれも再発行回数を加算）。
                            ・SearchAsync＝ロールに応じた閲覧範囲を自動適用。

  AccessService.cs          ★入退館受付の中核（設計書 6.4/6.4.1/6.5節）。
                            ・ScanAsync＝QR読取。トークン検証（無効/キャンセル/
                              読取済/期限切れ/受付時間前）→ TryConsumeAsync で排他的に
                              読取回数を加算 → グループ全員のステータス一括更新 →
                              全員分の AccessLogs を記録、を1トランザクションで実行。
                                1回目=入館 / 2回目=退館 / 3回目以降=エラー
                              エラー時は代表者行に1件だけエラーログを記録する。
                            ・ManualCheckOutAsync＝手動退館処理。★選択した個人のみを
                              退館済にする（グループ全員は更新しない）。TokenIdは
                              代表者の共通トークンを参照。受付・管理者ロールのみ。
                            ・SearchManualCheckOutTargetsAsync＝氏名・来館日で対象者検索。
                            ★読取結果メッセージは本ファイル冒頭の定数（日本語のみ）。

  MailDeliveryService.cs    メール送信と履歴記録の統括（設計書 5.2節）。
                            招待者（代表者）と予約登録者の2者のみへ送信し、
                            結果をそれぞれ独立したレコードとして MailHistory へ記録。
                            ★送信失敗は予約登録を失敗させない（履歴に失敗として残す）。

  HistoryService.cs         履歴照会（設計書 6.8節）。入退館履歴・メール送信履歴の検索、
                            CSV文字列生成、アーカイブ案内メッセージの組み立て。
                            ToText(...)＝ステータス・区分・ロールの日本語表示名を集約。
                            ToLocalText(...)＝UTC保存の日時をローカル時刻表示へ変換。

  MasterDataService.cs      会社名マスタ・拠点マスタの登録/編集/削除（管理者専用）。
                            変更内容は AuditLog へ記録（ロゴ画像はバイト数のみ記録）。
                            IsSingleSiteAsync＝Entryプランの拠点選択UI非表示判定。

  OperatorService.cs        操作ユーザー管理（管理者専用）。ロール・所属拠点・メールを
                            必須検証。★最後の有効な管理者を無効化・降格できないよう保護。
                            パスワードは監査ログに残さず「変更した事実」のみ記録。

  SystemSettingsService.cs  システム設定確認（管理者専用・読取専用）。DB方式・リトライ・
                            バックアップ運用・メール方式・印刷方式・ラベルプリセット・
                            ログアーカイブ・デモ有無の現在値を組み立てて返す。

  LogArchiveService.cs      ログ保持・アーカイブ（設計書 10.4節）。
                            RunAsync＝対象月（既定は前月）の履歴をCSV出力し、
                            保持期間を超えたデータをDBから削除。
                            CalculateDeleteThresholdUtc＝当月を含め保持月数分を残す。
                            IsNthBusinessDayOfMonth＝第N営業日の判定（土日を除外）。

  AuditService.cs           操作監査ログの記録。RecordInsert/Update/DeleteAsync で
                            変更前後の値をJSONとして保存。
                            AuditTargets に対象エンティティ名の定数。

  DemoDataSeeder.cs         デモ用サンプルデータ（設計書 19.3節）。
                            SeedIfEmptyAsync＝初回起動時のみ投入（冪等）。
                            ResetAsync＝全削除して再投入（管理者ロール専用）。
                            ★デモ用ログインの初期パスワードは DemoPassword 定数。

  ★本プロジェクトのSQL文はDB方式に依らず完全共通。

                            ・DateOnlyTypeHandler   date 列 ↔ DateOnly
                            ・TimeOnlyTypeHandler   time 列 ↔ TimeOnly

                              （SQL Server は Kind を保持しないため読取時に UTC を明示）
  RepositoryBase.cs         セッション解決とリトライ適用を集約。
                            ★呼び出し側からトランザクションが渡された場合は
                              リトライを適用しない（整合性を損なうため）。
  DatabaseInitializer.cs    スキーマ作成スクリプトの実行。db\01_CreateSchema.sql を
                            埋め込みリソースとして同梱し、GO行で分割して実行する。

  ■ Repositories
  ----------------------------------------------------------------
  VisitorRepository.cs      来館予約。グループ取得・グループ単位のステータス一括更新

                            EscapeLike＝LIKE検索のワイルドカードをエスケープ。
  QrTokenRepository.cs      QRトークン。TryConsumeAsync は WHERE句に現在値を含めて
                            同時読取時に後発の更新を失敗させる。
  AccessLogRepository.cs    入退館履歴。CreateManyAsync でグループ全員分を一括登録。
                            ToUtcRangeStart/EndExclusive＝画面のローカル日付をUTC範囲へ変換。
  MailHistoryRepository.cs  メール送信履歴。エラー内容は nvarchar(500) に収まるよう切詰め。
  SiteRepository.cs / OperatorRepository.cs / CompanyRepository.cs /
  AuditLogRepository.cs     各マスタ・監査ログ。


════════════════════════════════════════════════════════════════════
  4. Infrastructure.Data.SqlExpress / .AzureSql ── DB方式ごとの差分
════════════════════════════════════════════════════════════════════

  ■ SqlExpress（オンプレ版・デモ版）
  ----------------------------------------------------------------
  SqlExpressConnectionFactory.cs  接続ファクトリ。★デモ版（Demo:Enabled=true）は
                                  本クラスをそのまま使い、接続先のみ
                                  Demo:ConnectionString に切り替える。
  NoRetryPolicy.cs                リトライなし（社内LAN想定・即時に例外送出）。
  SqlExpressBackupService.cs      BACKUP DATABASE の実行。
                                  ★バックアップ圧縮(COMPRESSION)は Express Edition では
                                    未サポート（エラー1844）のため、エディションを判定して
                                    INIT, CHECKSUM に落とす。
                                  ★svc_visitor は最小権限のため通常運用では権限エラーになる。
                                    定時バックアップは scripts\Backup-VisitorMgmt.ps1 を
                                    特権アカウントで実行する（設計書 10.1節）。
  LocalArchiveStorage.cs          ログアーカイブCSVをローカルディスクへ保存（BOM付きUTF-8）。

  ■ AzureSql（クラウド版）
  ----------------------------------------------------------------
  AzureSqlConnectionFactory.cs    接続ファクトリ。★Encrypt=True /
                                  TrustServerCertificate=False を強制する（設計書11.2節）。
                                  認証はSQL認証に統一（Entra IDは将来拡張・実装しない）。
  AzureSqlRetryPolicy.cs          Polly による指数バックオフ（既定5回・最大10秒）。
                                  ★一時エラーのエラー番号は TransientErrorNumbers に定義
                                    （40501=スロットリング、40613=DB利用不可 等）。
  AzureSqlBackupService.cs        自動バックアップに委譲（独自実装は持たない）。
  AzureBlobArchiveStorage.cs      ログアーカイブCSVを Azure Blob Storage へ保存。

 13. 編集ガイド（◯◯を変えたい時はどこを触るか）
════════════════════════════════════════════════════════════════════

【DBをSQL Server ExpressからAzure SQL Databaseに変えたい】★本システムの中核
  → appsettings.json の Database:Provider を "AzureSql" に変更して再起動するだけ。
    接続文字列 Database:ConnectionStrings:AzureSql も設定する。
  ※コードの変更は一切不要。切替の登録は
    VisitorManagement.Composition\ServiceCollectionExtensions.cs の AddDatabaseProvider。
  ※運用途中の切替は非稼働日にバッチで実施（設計書13.3節・稼働中の無停止移行は非対応）。

【QRコードの有効時間（30分前〜2時間後）を変えたい】
  → VisitorManagement.Core\VisitRules.cs の ValidFromOffset / ValidToOffset
  ※発行・読取・再送信のすべてが同メソッドを呼ぶため、ここ1か所で全体に反映される。

【1回目=入館/2回目=退館 の読取ロジックを変えたい】
  → VisitorManagement.Application\Services\AccessService.cs の ScanAsync
  ※読取回数は QRTokens.UsedCount で管理（0→1→2）。
  ※3回目以降は AccessLogs にエラーを記録するだけでステータスは変えない。

【当日受付の「登録＝入館」の扱いを変えたい】★設計書からの変更仕様
  → VisitorManagement.Application\Services\ReservationService.cs の CreateAsync
    （isWalkIn の分岐。初期ステータス・UsedCount の初期値・入館履歴の作成）
  ※発行時刻を入館時刻として AccessLogs に記録する。
  ※QRトークンを UsedCount=1 で発行することで、AccessService 側は改修せずに
    「発行したQRの最初の読取＝退館」を実現している。
  ※画面の案内文は WebReception\Resources\ReceptionTexts.cs
    （CompletedTitle / CompletedDescription / CheckedInAtFormat / ScanHint）。

【受付画面に表示するメッセージを変えたい】
  → 読取結果のメッセージ = AccessService.cs 冒頭の定数
    （MessageCheckedIn / MessageCheckedOut / MessageAlreadyCheckedOut 等）
  → 画面の見出し・案内文 = WebReception\Resources\ReceptionTexts.cs の
    ReceptionResultTexts
  ※読取結果表示画面は多言語対応の対象外（日本語のみ・設計書8.3節）。

【当日受付画面の日英併記の文言を変えたい】★顧客ごとの調整
  → VisitorManagement.WebReception\Resources\ReceptionTexts.cs
  → メール文面 = VisitorManagement.Infrastructure.Mail\MailTemplates.cs
  ※調整対象の行には行頭に「// ★レイアウト調整」が付いている。
    このキーワードでソース全文検索すると調整箇所が一覧できる（設計書18章 確認事項No.3）。
  ※管理画面（WinForms）は日本語のみ。多言語化の対象外。

【権限（ロール）ごとにできることを変えたい】
  → 判定ロジック = VisitorManagement.Core\Security\PermissionPolicy.cs（ここ1か所）
  → 画面のメニュー表示 = WinFormsApp\Forms\MainForm.cs の ApplyPermissions
  → 各画面のボタン活性 = 各 Form.cs の ApplyPermissions
  → 受付Webの制御 = Reception.cshtml.cs / WalkIn.cshtml.cs / Endpoints\AccessApi.cs
  ※UI側で隠すだけでなく、サービス層とAPIでも必ず判定する（多層防御）。

【履歴の閲覧範囲（一般=自分の登録分 等）を変えたい】
  → PermissionPolicy.ResolveViewScope（ここ1か所）
  ※各サービスの検索メソッドが ApplyViewScope を呼んで検索条件へ反映する。

【ラベルのサイズ（プリセット2・3）を設定したい】★導入時によく使う
  → appsettings.json の Printing:LabelPresets:Preset2 / Preset3 に
    WidthMm / HeightMm / LabelPartNumber を設定する。
  → 拠点ごとの使用プリセットは「拠点マスタ管理」画面で選択（Sites.LabelSizeType）。
  ※既定ではプリセット1（幅60mm×高さ110mm）のみ設定済み。

【ラベルの印刷レイアウトを変えたい】
  → 本番（実機印刷）= P-touch Editor でテンプレート(.lbx)を編集し、
    appsettings.json の Printing:LbxTemplatePath を指定。
    オブジェクト名は Ql800LabelPrinter.cs 冒頭の定数と一致させる。
  → デモ（PDFプレビュー）= Infrastructure.Printing\DemoPdfLabelPrinter.cs の
    DrawLabelPreview（配置）/ DrawHeader / DrawFooter。

【メール送信方式（SendGrid/SMTP）を変えたい】
  → appsettings.json の Mail:Provider を "SendGrid" / "Smtp" に変更して再起動。
  ※切替の登録は Composition\ServiceCollectionExtensions.cs の AddMailProvider。

【メールの宛先ルールを変えたい】
  → VisitorManagement.Application\Services\MailDeliveryService.cs の SendInvitationAsync
  ※現仕様は「招待者（代表者）と予約登録者の2者のみ」。同行者個人へは送信しない

════════════════════════════════════════════════════════════════════
 14. ログ管理（どのフォルダに何のログが出るか）
════════════════════════════════════════════════════════════════════
  ログは「①アプリ動作ログ（ファイル）」と「②操作監査ログ（DB）」の2種類がある。

  ── ① アプリ動作ログ ────────────────────────────────────
  ◇管理アプリ（WinForms）
     出力先：実行ファイルと同じフォルダの logs\app-YYYYMMDD.log
     実装  ：WinFormsApp\Logging\FileLoggerProvider.cs（日付ごとに分割）
     形式  ：日時 [レベル] カテゴリ - メッセージ
             例) 2026-08-25 15:40:32.323 [WRN] AuthenticationService -
                 ログインに失敗しました（パスワード不一致）。LoginId: admin
  ◇受付Web（ASP.NET Core）
     標準のログ設定（appsettings.json の Logging セクション）に従う。
     コンソール出力。IIS配下やサービス化した場合は各基盤のログへ。
  ◇バッチ（BatchRunner）
     コンソール出力。タスクスケジューラから実行する場合は
     リダイレクト（> ログファイル）で保存する。
  ◇記録される内容
     ・ログイン失敗、予約登録、入退館受付、メール送信結果、
       バックアップ・アーカイブの実行結果、各種エラー
  ◇用途：不具合調査・動作確認（主に技術者向け）。

  ── ② 操作監査ログ（データベース） ───────────────────────────
  ◇保存先：DBテーブル AuditLog（誰が・いつ・何を変更したか）
  ◇記録元：Application\Services\AuditService.cs
           （拠点マスタ・会社名マスタ・操作ユーザー・運用設定の登録/更新/削除）
  ◇内容  ：TargetEntity（対象）・TargetId・ChangeType（登録/更新/削除）・
           OldValue / NewValue（JSON）・ChangedAt・ChangedByOperatorId
  ◇注意  ：パスワードは記録しない（「変更した事実」のみ）。
           ロゴ画像はバイト数のみ記録する（可読性のため）。
  ◇DB方式の切替自体の監査テーブルは設けない（非稼働日バッチ運用のため・設計書11.5節）。

  ── ③ 入退館履歴・メール送信履歴（業務ログ） ─────────────────────
  ◇AccessLogs / MailHistory テーブル。管理アプリの「履歴照会」画面で照会・CSV出力。
  ◇DB上の保持期間は直近3か月。それ以前は月次バッチでCSVへアーカイブ後に削除する
    （設計書 10.4節）。

  ・ソリューションは .slnx 形式（.NET 10 SDK 既定）。
    「VisitorManagement.sln」は存在しないので dotnet build に渡さないこと。

      dbo.Visitors にフィルター選択インデックス UQ_Visitors_GroupRepresentative

      同テーブルへの DDL/DML がエラー1934で失敗する。
      アプリ（Microsoft.Data.SqlClient）は既定ONのため対応不要。
