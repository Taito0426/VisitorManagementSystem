 本書は詳細設計書（版数2.7）の各章に対応した動作検証項目です。
 開発時に実施済みの項目には [〇] を記載し、確認方法を付記しています。
 環境（実機プリンタ・Azure SQL Database・メールサーバー）が必要なため
 未実施の項目は [ ] のままです。


■ 凡例
  [ ] 未確認  /  [〇] OK  /  [!] 不具合あり（備考に内容を記載）
  対象ロール表記: 管理者 / 受付 / 一般
  ★ = 設計書のQ&Aで確定した重要仕様。特に注意して確認すること
  ◆ = 実機・外部サービスが必要なため開発環境では未実施

 6. 入退館受付（設計書 6.4節・8.3節）★本システムの中核
--------------------------------------------------------------------
[〇] 受付Webにログインすると「入退館受付」画面が表示される
[〇] ★1回目の読み取りで代表者・同行者の全員が「入館中」になる
[〇] ★2回目の読み取りで代表者・同行者の全員が「退館済」になる
[〇] ★3回目以降の読み取りはエラーになり、ステータスは変わらない
[〇] 読み取り結果にグループ全員の氏名・会社名・区分（代表者/同行者）が表示される
[〇] 読み取り結果が大きな文字で表示される
[ ] 読み取り結果が一定時間（15秒）で自動的に消える
[ ] 画面をクリックすると入力欄にフォーカスが戻る
[〇] 未登録のQRコードを読み取るとエラーになり、AccessLogs に記録されない
[〇] 期限切れのQRコードはエラーになり、AccessLogs にエラーが記録される
[〇] 受付可能時間の前（30分前より早い）に読み取るとエラーになる
[〇] キャンセル済みの予約のQRコードはエラーになる
[〇] 無効化されたQRコードはエラーになる
[〇] ★1回の読み取りでグループ内の来館者ごとに AccessLogs が1件ずつ記録される
[〇] AccessLogs の TokenId は全員が代表者の同一トークンを参照している
[〇] エラー時の AccessLogs は代表者の1件のみ記録される
[〇] キャンセル済みの同行者は一括更新の対象外になる
[〇] 同時読み取り時に二重処理されない（排他制御）
[ ] 実機のQRリーダー（キーボードエミュレーション）で読み取れる ◆
[ ] QRリーダーの末尾Enterで自動的に受付処理が実行される ◆

  ── ★カメラ読取（USB QRリーダーとの併用。設計書 8.3節の拡張） ──────────
[〇] ★localhost（セキュアコンテキスト）では「カメラで読み取る」ボタンが表示される
[〇] ★同梱の jsQR が読み込まれ、BarcodeDetector 非対応環境でも復号できる

[〇] ★アプリが発行した実物のQR画像を canvas 経由で復号できる
[〇] ★カメラ読取で入退館受付が完了する（合成カメラ映像で退館まで確認）
[〇] ★カメラ読取と USB QRリーダーの双方が同じ画面で使える
[〇] ★AccessLogs.DeviceInfo の末尾で読取経路（／カメラ ／スキャナー）を判別できる
[〇] ★同じQRをかざし続けても受付は1回だけ（161回の復号試行で送信1回）
[〇] ★QRを一度画角から外して再度かざすと、あらためて受付される
[〇] ★カメラの使用を拒否すると日本語のエラーメッセージが表示され、画面は操作可能なまま
[〇] ★映像が届かない端末でもボタンが押せなくなる状態にならない
[ ] HTTP でLANのIPを直接開くと、ボタンが出ず「HTTPS接続が必要です」と表示される
[ ] Android実機のカメラで読み取れる（USBポートフォワーディングで検証）
[ ] 背面カメラが選択される（facingMode: environment）
[ ] iPhone実機のカメラで読み取れる ◆（HTTPS化が前提）
[ ] 画面をバックグラウンドにするとカメラが停止し、電池を消費しない
