# 来館者記録管理システム 導入手順書

本書は詳細設計書（版数2.7）13章「導入・移行手順」に基づく作業手順です。

---

## 1. システム構成の選択

| パターン | DB / インフラ | 想定顧客 |
|---|---|---|
| A: オンプレ版 | SQL Server Express + 社内サーバー機 | 社内LANのみで完結、クラウド費用を抑えたい |
| B: クラウド版 | Azure SQL Database + Azure App Service + SendGrid | 複数拠点・リモート受付・高可用性を重視 |

アプリケーションのバイナリは共通です。`appsettings.json` の `Database:Provider` を
`"SqlExpress"` / `"AzureSql"` で切り替えるだけで両対応します（設計書 4.4節）。

## 2. 新規導入（オンプレ版）— 設計書 13.1節

### ① データベースの作成

```
sqlcmd -S .\SQLEXPRESS -E -I -i db\00_CreateDatabase_SqlExpress.sql
sqlcmd -S .\SQLEXPRESS -E -I -d VisitorMgmt -i db\01_CreateSchema.sql
```

> **重要**: `sqlcmd` には必ず `-I`（QUOTED_IDENTIFIER 有効化）を付けてください。
> `dbo.Visitors` にフィルター選択インデックス（1予約グループに代表者1名を保証）があるため、
> `-I` なしでは同テーブルへの DDL/DML がエラー 1934 で失敗します。

### ② サービス用SQLログインの作成（最小権限）

```
sqlcmd -S .\SQLEXPRESS -E -I -i db\02_CreateLogin_SqlExpress.sql -v SvcPassword="<強固なパスワード>"
```

`svc_visitor` には `db_datareader` / `db_datawriter` のみを付与します。
sysadmin 等の強い権限は付与しません（設計書 11.1節）。

### ③ appsettings.json の設定

`Database:Provider` を `"SqlExpress"` に設定し、接続文字列を投入します。

接続文字列中のパスワードは平文で保存せず、DPAPI で暗号化してください（設計書 11.3節）。

```
powershell -ExecutionPolicy Bypass -File scripts\Protect-Secret.ps1
```

表示された `ENC:...` の値を `Database:ConnectionStrings:SqlExpress` に設定します。
アプリは起動時に自動で復号します。暗号化した値は**暗号化を行ったマシン上でのみ**復号できます。

対象キー: `Database:ConnectionStrings:*` / `Demo:ConnectionString` /
`Mail:SendGrid:ApiKey` / `Mail:Smtp:Password` / `LogArchive:AzureBlob:ConnectionString`

### ④ 定時バッチの登録

```
powershell -ExecutionPolicy Bypass -File scripts\Register-ScheduledTasks.ps1 ^
    -BackupPath "D:\Backup" ^
    -BatchRunnerPath "C:\Program Files\VisitorManagement\VisitorManagement.BatchRunner.exe"
```

| タスク | 実行 | 内容 |
|---|---|---|
| VisitorMgmt-Backup | 毎日 23:00 | データベースのバックアップ＋30日超のファイル削除（設計書 10.1節） |
| VisitorMgmt-LogArchive | 毎日 01:00 | 当日が月内第1営業日のときのみ月次CSVアーカイブを実行（設計書 10.4節） |

> バックアップタスクの実行アカウントには `BACKUP DATABASE` 権限（sysadmin または
> db_backupoperator）が必要です。アプリのサービスアカウント `svc_visitor` は
> 最小権限のためバックアップを実行できません。

### ⑤⑥ 拠点・マスタ・操作ユーザーの登録

管理アプリ（`VisitorManagement.WinFormsApp.exe`）を起動します。
操作ユーザーが1件も登録されていない初回起動時は **初期セットアップ画面** が表示されるので、
最初の拠点と管理者アカウントを登録してください。

以降、以下をメニューから登録します。

1. 拠点マスタ管理 … 契約プランに応じた拠点数分（Entry=1拠点 / Standard=2〜3拠点 / Professional=4拠点以上）
2. 会社名マスタ管理 … 来館予約入力を補助する会社名
3. 操作ユーザー管理 … 権限ロール・所属拠点・メールアドレス（**いずれも必須**）

### ⑦ ラベルプリンタの設定

1. 感熱式ラベルプリンタ（ブラザー QL-800 想定）のドライバと **b-PAC SDK** をインストール
2. P-touch Editor でラベルテンプレート（.lbx）を作成し、以下の名前でオブジェクトを配置

   | オブジェクト名 | 内容 |
   |---|---|
   | `qrImage` | QRコード画像 |
   | `companyName` | 拠点のラベル表示社名 |
   | `visitorName` | 来館者氏名 |
   | `visitDate` | 来館日 |
   | `logoImage` | ロゴ画像（任意） |

3. `appsettings.json` の `Printing:LbxTemplatePath` にテンプレートのパスを設定
4. 拠点マスタ管理画面でラベルサイズプリセットを選択
   - プリセット1（幅60mm×高さ110mm）が標準搭載
   - プリセット2・3は寸法未設定です。使用する場合は導入時ヒアリングに基づき
     `Printing:LabelPresets:Preset2` / `Preset3` に寸法を設定してください（設計書 18章 確認事項No.2）
5. 当日受付端末に接続し印字テストを実施

### ⑧ QRリーダーの設定

キーボードエミュレーション方式（HIDモード）で使用します。
**読取値の末尾に Enter（CR）を送出する設定**にしてください。受付画面は Enter を
トリガーとして受付APIへ送信します（設計書 8.3節）。

### ⑨ アプリケーションの配布

管理アプリは .NET 10 で動作するため、OS標準搭載のランタイムは利用できません。
自己完結型（self-contained）で発行し、ランタイムの事前インストールを不要にします。

```
dotnet publish src\VisitorManagement.WinFormsApp -p:PublishProfile=SelfContained -c Release
dotnet publish src\VisitorManagement.WebReception -p:PublishProfile=SelfContained -c Release
```

## 3. 新規導入（クラウド版）— 設計書 13.2節

1. Azure SQL Database を作成し、`db\01_CreateSchema.sql` を実行（接続時に `-I` を指定）
2. `db\02_CreateUser_AzureSql.sql` で `svc_visitor` を作成
   （Azure SQL は USE 文が使えないため、master と対象DBに個別接続して2段階で実行）
3. Azure App Service をプロビジョニングし、アプリケーションを配置
   - Service Tier は想定同時接続数（1拠点あたり端末10台以下）に応じて汎用目的の下位〜中位を初期選定
4. `appsettings.json` の `Database:Provider` を `"AzureSql"` に設定
   - 接続情報は **Azure Key Vault 参照** または環境変数（`VISITORMGMT_` プレフィックス）で設定
   - Linux App Service では DPAPI を利用できません
5. 自動バックアップ設定（PITR保持期間、必要に応じ LTR）を確認
6. SendGrid アカウントを設定し、`Mail:Provider` を `"SendGrid"` に設定
7. 拠点・初期マスタ・操作ユーザーを登録（オンプレ版⑤⑥と同様）
8. `LogArchive:StorageMode` を `"AzureBlob"` に設定し、ログアーカイブバッチを
   Azure Functions／WebJobs で定時実行するよう設定

## 4. DB方式の変更（非稼働日バッチ切替）— 設計書 13.3節

稼働中の無停止移行はサポート対象外です。非稼働日に以下の順で実施します。

| 手順 | 内容 |
|---|---|
| ① 事前準備 | 移行先DBを用意し、`01_CreateSchema.sql` でスキーマを作成。作業日を関係者へ周知 |
| ② エクスポート | 非稼働時間帯に既存DBの全データをエクスポート（BCP／スクリプト／Azure DMS） |
| ③ インポート | 移行先DBへインポートし、件数照合等の整合性チェック |
| ④ 設定切替 | `Database:Provider` と接続文字列を変更 |
| ⑤ 動作確認 | アプリを再起動し、予約登録→QR発行→入館→退館→履歴照会を確認して稼働再開 |

## 5. 導入時ヒアリングが必要な項目

設計書が「導入時に個別設定」としている項目です。

| 項目 | 設定先 | 既定値 |
|---|---|---|
| ラベルサイズ プリセット2・3 | `Printing:LabelPresets:Preset2` / `Preset3` | 未設定 |
| ラベルプリンタ機種 | `Printing:PrinterName` / `LbxTemplatePath` | QL-800 想定 |
| メール送信方式 | `Mail:Provider` | SendGrid |
| バックアップ保存先・保管期間 | `Backup:SqlExpress` | `D:\Backup\` / 30日 |
| ログアーカイブ保管先 | `LogArchive:StorageMode` / `Local` / `AzureBlob` | Local |
| 多言語文言の企業別調整 | ソース内の `// ★レイアウト調整` コメント行 | 標準文言 |
