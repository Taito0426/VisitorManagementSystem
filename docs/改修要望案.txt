入退館受付
・USBスキャナーと併用してスマホのカメラで入退館チェックできるようにしてほしい。
  → 対応済み（受付スタッフの業務用端末での利用を想定）。
     受付画面に「カメラで読み取る」を追加し、USB QRリーダーと併用できるようにした。
     復号した文字列を既存の submitScan() に渡すため、サーバー側
     （AccessApi／AccessService／DBスキーマ）は変更していない。
     ・BarcodeDetector があれば使用し、無ければ同梱の jsQR で復号
       （Apache-2.0・無改変。iOS Safari や Windows版Chromeでは
         BarcodeDetector が使えないため必須。CDNは参照しない）
     ・同じQRをかざし続けている間は受付を繰り返さない
       （エラー履歴の量産を防止。連続未検出が続いた場合のみ再受付）
     ・AccessLogs.DeviceInfo の末尾に「／カメラ」「／スキャナー」を付け、
       読取経路を履歴照会で判別できるようにした
     ・あわせて DeviceInfo が nvarchar(100) を超えると桁あふれエラーになる
       既存の潜在不具合を AccessService 側で丸めて解消した
     Reception.cshtml / AccessService.cs / site.css / wwwroot/js/jsQR.js

     ★本番運用にはHTTPS化が必要（ブラウザのカメラAPIはHTTPSまたはlocalhostのみ）。
       クラウドサーバーの契約は不要で、受付Webは現在のオンプレ機のままでよい。
         推奨: 独自ドメイン＋Let's Encrypt（DNS-01）… ドメイン代 年1,000〜4,000円程度
               AレコードをLAN内プライベートIPに向ければ外部公開も不要
         代替: 自己署名／社内CA（0円。全端末にCA証明書の導入が必要）
       HTTPS化前でも、開発PCのlocalhostとAndroidのUSBポートフォワーディングで
       実機カメラの検証は可能（費用0円）。iPhone実機の確認はHTTPS化後。

デバッグ・デモ支援
・PDFレイアウト確認ボタンを予約確認画面にデバッグ用で追加してください。
  → 対応済み。管理アプリの来館予約管理（一覧）画面に「PDFレイアウト確認」ボタンを
     追加した。選択行の予約について、ラベル＋メール文面のA4 PDFを出力して
     既定のビューアで開く。
     表示条件は ILabelPdfPreview が解決できるとき＝デモ版構成
     （Printing:Provider="PdfPreview"）または Debugビルドのとき。
     Debugビルドでは実機印刷構成（Ql800）でも DemoPdfLabelPrinter を
     ILabelPdfPreview として追加登録し、PDFで確認できるようにした。
     Releaseビルドの商用構成ではボタンごと現れない。
     ServiceCollectionExtensions.cs / ReservationListForm.cs

・本番以外では登録時のメール送信を行わず、送信結果に「テスト」と表示してください。
  → 対応済み。本番以外＝Demo:Enabled=true または Debugビルド。
     ・DI登録で IMailSender を DemoMailSender（外部送信しないモック）に固定した。
       Debugビルドで本番のメール設定が入っていても実在の宛先へ誤送信しない。
     ・IMailSender に IsTestMode を追加し、MailDeliveryResult 経由で画面へ伝える。
     ・送信結果の表示（予約登録完了ダイアログ／メール再送信結果／当日受付の完了画面）
       を「テスト（実際には送信していません）」に切り替えた。
     ・MailHistory への記録は従来どおり成功として残す（履歴照会のデモが成立するため）。
     IMailSender.cs / MailSenderBase.cs / DemoMailSender.cs /
     MailDeliveryService.cs / ServiceCollectionExtensions.cs /
     ReservationEditForm.cs / ReservationListForm.cs / WalkIn.cshtml / ReceptionTexts.cs

権限（RBAC）
・一般ユーザーの来館予約管理に新規追加ボタンがなく予約できない状態を修正してください。
  → 対応済み。設計書 11.6節の権限マトリクスを変更し、一般ロールにも来館予約の
     登録・編集・キャンセルを許可した（対象は自分が登録した予約のみ）。
     ・削除（履歴ごと消える操作）とメール再送信は従来どおり管理者・受付のみ
     ・当日受付登録・入退館受付・手動退館処理も従来どおり管理者・受付のみ
     ・他人が登録した予約は一覧に表示されず、予約IDを直接指定しても
       サービス層（Update/Cancel）で権限エラーとなる
     PermissionPolicy.cs / ReservationService.cs / ReservationListForm.cs
     ※設計書（.docx 正本）も版数2.7として改版済み。
       11.6節の権限マトリクス、6.10節の一般ロール説明、表紙の版数、改訂履歴を更新。
       改訂前の原本は docs\来館者記録管理システム_詳細設計書_v2.6(改訂前).docx に保存。

 A4上半分にQRコードレイアウト、下半分の左に予約者用メール、右側に来訪者代表メールへの送信分を表示

       それでも溢れる場合のみ末尾を「…（以下省略 / truncated）」で省略する
     ・当日受付は控えメールを送信しない運用のため、左カラムに注記を表示する
     ・確認用の導線として、管理アプリのQRコード表示画面にも
       「レイアウトをPDFで確認」ボタンを追加した（デモ版構成のときのみ表示）
