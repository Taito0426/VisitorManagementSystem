# 来館者記録管理システム 運用マニュアル

本書は詳細設計書（版数2.7）10章「バックアップ・運用設計」に基づく運用手順です。

---

## 1. バックアップ

### 1.1 SQL Server Express（オンプレ版）— 設計書 10.1節

SQL Server Express は SQL Server Agent が利用できないため、
Windows タスクスケジューラから PowerShell スクリプトを定時実行します。

| 項目 | 内容 |
|---|---|
| 実行方式 | タスク `VisitorMgmt-Backup` → `scripts\Backup-VisitorMgmt.ps1` |
| 実行時刻 | 毎日 23:00（`Backup:SqlExpress:DailyTime`） |
| 保存先 | サーバー機のローカルディスク（別ドライブ推奨）。NAS等への二次コピーを推奨 |
| 保管期間 | 30日（超過分はスクリプトが自動削除） |

**手動実行**

```
powershell -ExecutionPolicy Bypass -File scripts\Backup-VisitorMgmt.ps1 -BackupPath "D:\Backup"
```

> **注意**: バックアップ圧縮（`WITH COMPRESSION`）は **Express Edition では未サポート**です。
> スクリプトはエディションを判定し、Express では `INIT, CHECKSUM` のみを指定します。
> （詳細設計書 10.1節のサンプルSQLは `COMPRESSION` を含んでいますが、
>  Express で実行するとエラー 1844 となるため実装側で補正しています）

> **権限**: 実行アカウントに `BACKUP DATABASE` 権限（sysadmin または db_backupoperator）が必要です。
> アプリのサービスアカウント `svc_visitor` は最小権限のため実行できません（設計書 11.1節）。

### 1.2 リストア手順

```
sqlcmd -S .\SQLEXPRESS -E -I -Q "ALTER DATABASE [VisitorMgmt] SET SINGLE_USER WITH ROLLBACK IMMEDIATE;"
sqlcmd -S .\SQLEXPRESS -E -I -Q "RESTORE DATABASE [VisitorMgmt] FROM DISK = N'D:\Backup\VisitorMgmt_20260825_230000.bak' WITH REPLACE;"
sqlcmd -S .\SQLEXPRESS -E -I -Q "ALTER DATABASE [VisitorMgmt] SET MULTI_USER;"
```

リストア後、アプリケーションを再起動し、予約一覧・履歴照会が正しく表示されることを確認します。

### 1.3 Azure SQL Database（クラウド版）— 設計書 10.2節

自動バックアップが標準搭載されており、追加の実装・運用作業は不要です。

| 項目 | 内容 |
|---|---|
| フル / 差分 / ログ | 自動（Microsoft 管理） |
| ポイントインタイムリストア | 既定7日（最大35日まで延長可） |
| 長期保存（LTR） | 任意設定。コストに直結するため契約プランに応じて顧客と合意のうえ設定 |
| リストア | Azure Portal または Azure CLI からポイントインタイムリストア。**新規DBとして復元される点に留意** |

### 1.4 復元テスト

いずれの方式も、**バックアップの復元テストを年1回程度実施**してください。

## 2. ログ保持・アーカイブ — 設計書 10.4節

入退館履歴（AccessLogs）とメール送信履歴（MailHistory）は DB 上に直近3か月分のみを保持します。

| 項目 | 内容 |
|---|---|
| DB保持期間 | 直近3か月（`LogArchive:DbRetentionMonths`） |
| CSV出力 | 毎月、翌月の第1営業日（例: 1月分を2月第1営業日に出力） |
| DB削除 | CSV出力から3か月経過後（例: 1月分は4月に削除） |
| 形式 | CSV（1テーブル・1か月単位。Excelで開けるBOM付きUTF-8） |
| 保管先 | オンプレ版=ローカルディスク / クラウド版=Azure Blob Storage |

### 2.1 自動実行

タスク `VisitorMgmt-LogArchive` が毎日01:00に起動し、
当日が月内第1営業日でなければ何もせず終了します。
（タスクスケジューラでは「第N営業日」を直接表現できないための方式です）

### 2.2 手動実行

```
:: 前月分を出力し、保持期間超過分をDBから削除
VisitorManagement.BatchRunner.exe log-archive

:: 特定月を出力（削除は行わない）
VisitorManagement.BatchRunner.exe log-archive --month 2026-07 --no-delete
```

終了コード: `0`=正常終了 / `1`=引数エラー / `2`=実行時エラー

### 2.3 アーカイブ済み期間の照会

履歴照会画面で保持期間より前の期間を指定すると、
アーカイブCSVの保管場所を案内するメッセージが表示されます。
該当期間のデータはCSVファイルを直接参照してください。

## 3. 障害復旧（DR）— 設計書 10.5節

### 3.1 構成

本番機（サーバー兼管理PC）＋定期自動バックアップ＋予備PC＋本手順書。
**目標復旧時間（RTO）は30分以内**です。

予備PCは本番機と**同一拠点**に設置し、平常時から本番同等の
OS・ミドルウェア・アプリケーションをセットアップ済みの状態で待機させます。
これにより復旧作業を「バックアップからのDB復元＋接続先切替」のみに限定します。

### 3.2 復旧手順

| 手順 | 内容 | 目安 |
|---|---|---|
| ① | 障害発生を検知 | — |
| ② | 予備PCを起動（SQL Server Express セットアップ済み） | 3分 |
| ③ | 最新バックアップファイルから 1.2 の手順で `RESTORE DATABASE` | 10分 |
| ④ | 接続文字列・IPアドレス等の切替（DNS/ホスト名の付け替え、または固定IP引き継ぎ） | 10分 |
| ⑤ | 動作確認（予約登録→QR発行→入館→退館→履歴照会） | 5分 |

> ④ で予備PC上の `appsettings.json` を書き換える場合、DPAPI で暗号化した接続文字列は
> **暗号化を行ったマシンでしか復号できません**。予備PC上で
> `scripts\Protect-Secret.ps1` を実行して値を作り直してください。
> 平常時に予備PC用の設定ファイルを準備しておくことを推奨します。

### 3.3 クラウド版

Azure App Service / Azure SQL Database の可用性は Microsoft の SLA に準じます。
上記のDR方針は主にオンプレ版（パターンA）を対象とします。

## 4. 日常運用上の留意点

### 4.1 sqlcmd 実行時の注意

`dbo.Visitors` にはフィルター選択インデックス `UQ_Visitors_GroupRepresentative`
（1予約グループに代表者1名のみを保証）があります。
SQL Server の仕様上、同テーブルへの INSERT/UPDATE/DELETE は
QUOTED_IDENTIFIER が ON でなければ失敗します（エラー 1934）。

- アプリケーション: Microsoft.Data.SqlClient は既定で ON のため対応不要
- **sqlcmd / バッチ: 既定が OFF のため `-I` オプションを必ず付けてください**

### 4.2 メール送信の失敗確認

メール送信の失敗は予約登録自体を失敗させません。
送信結果は MailHistory に記録されるため、履歴照会画面の
「メール送信履歴」タブで結果=失敗のレコードを定期的に確認してください。

招待者がメールを紛失・未着の場合は、予約管理画面の「メール再送信」で
招待者・予約登録者の双方へ再送信できます（当日受付分は対象外）。

### 4.3 監査ログ

マスタ変更（拠点・会社名・操作ユーザー）と運用設定変更は AuditLog テーブルに記録されます。
必要に応じて直接クエリで確認してください。

```sql
SELECT TOP 100 ChangedAt, TargetEntity, ChangeType, TargetId, ChangedByOperatorId
FROM   dbo.AuditLog
ORDER BY ChangedAt DESC;
```

### 4.4 アプリケーションログ

管理アプリは実行ファイルと同じフォルダの `logs\app-yyyyMMdd.log` に出力します。
受付Webは標準の ASP.NET Core ログ設定（`appsettings.json` の `Logging`）に従います。

## 5. DB方式・メール方式の切替

稼働中のシームレスな切替はサポート対象外です。
非稼働日（休業日・夜間等の業務停止時間帯）に切替作業を実施してください。
手順は「導入手順書」4章を参照してください。

システム設定確認画面（管理者専用）で現在値を参照できますが、
**画面からの変更はできません**。設定ファイルの編集＋アプリケーション再起動が必要です。
